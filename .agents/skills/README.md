- `poteto-mode/playbooks/multi-phase-plan.md`: changed its eight `pstack/skills/...` path examples to `.agents/skills/...`, including the Node plan-checker helper and skill/playbook file lookups.
- Anchored bundled helper invocations to `.agents/skills/` in `poteto-mode/compatibility.md`, `poteto-mode/playbooks/babysit.md`, `orchestrate.md`, `shipping.md`, and `worktree-cleanup.md`, plus `show-me-your-work/SKILL.md`. This covers the watcher, orchestration CLI, worktree audit, and decision-log helper.
- `poteto-mode/scripts/worktree-audit.sh`: fail clearly if `jq` is unavailable or rejects the PR inventory, rather than silently treating a failed parse as no open PRs; the best-effort empty inventory still applies when neither supported forge command can provide PR data. Read Git's NUL-delimited worktree paths and statuses, report exact shell-safe worktree paths, enumerate untracked, ignored, and submodule paths in a JSON `DATA` column, and hold these worktrees for inspection. Stream shell-escaped paths through a temporary file before JSON encoding so large inventories do not exceed the OS argument limit; treat every tracked submodule gitlink as a manual hold rather than descending into its contents; search recent-chat transcripts with literal raw or JSON-escaped path matching and surface search errors.
- `poteto-mode/scripts/watch-pr/{types,policy,render}.ts`: treat GitHub's `REVIEW_REQUIRED` decision as a merge-gate blocker and render it as an approval requirement, so passing checks cannot incorrectly produce `READY`. `policy.test.ts` covers the blocked merge state with passing CI.
- `poteto-mode/scripts/orch/store.ts`: protect an existing verifier-authored ledger verdict from a worker report that omits verifier identity; an explicit later verifier can still update the verdict. `orch.test.ts` covers both paths.
- `poteto-mode/scripts/orch/store.ts`: serialize lock creation, stale recovery, forced takeover, and release with `.orch.lock.guard`; lock generations use random tokens and recovery rechecks exact contents before unlinking. A leftover coordination guard fails closed and can be removed only after verifying no writer remains. A failed close retains its release callback and can retry after temporary guard contention. `orch.test.ts` covers stale-lock replacement, same-process replacement release, and close retry after guard contention.
- `poteto-mode/playbooks/worktree-cleanup.md`: require listing exact untracked or ignored paths and getting explicit user confirmation before `git worktree remove --force` or `rm -rf` can delete them.
- Other intra-skill and cross-skill relative references remain unchanged; for example, `architect/references/rationale-template.md` still resolves to the imported `arena/SKILL.md`.
